## 9. Documentation problems

### D1. Root README is materially stale

The root `README.md` still presents an older Incident 003 state. In
particular, it describes the earlier v2 raw/relative-time result and says that
no destructive Incident 003 privacy observation exists, even though the v3
paired raw, relative-time, and temporal-ablation stages are complete and frozen.

For a new reader, the repository landing page therefore conflicts with the
paper and current tracked result documents.

### D2. Manuscript artifact wording still points to issue #35 as pending work

The manuscript Methodology/Limitations language says provider-observation
replay/distribution awaits work tracked in issue #35. Issue #35 is now closed
after the archive RFC, manifest, and verifier merged. The true current boundary
is more specific: archive **design and verification tooling exist**, while
private materialization/distribution has not been provisioned.

This does not change the current Level-1-only conclusion, but the issue-number
wording is stale.

### D3. Historical fresh-clone audit is easy to mistake for current status

`docs/FRESH_CLONE_REPRODUCIBILITY_AUDIT.md` is properly pinned to an older
commit and accurately describes that historical run. The root README links it
without emphasizing that a newer clean-room check now exists. A preprint reader
could reasonably mistake its 790-pass snapshot for the present repository
state.

### D4. TeX prerequisites are underspecified for a clean machine

`paper/README.md` says to use a "normal TeX installation" plus `latexmk`.
That is adequate for an experienced LaTeX user but not sufficient to guarantee
a clean CI/container build. The clean Ubuntu runner did not have `latexmk`.

### D5. The artifact-level distinction is spread across several documents

The RFC and manifest correctly distinguish design from actual distribution,
but a new reader must combine `paper/README.md`,
`docs/FROZEN_ARTIFACT_ARCHIVE_RFC.md`, and the manifest to understand that
Level 1 is available while Levels 2/3 are not. A short authoritative statement
in the public README/preprint reproducibility section would reduce ambiguity.

## 12. Team-executed 3–5 sentence contribution summary

DiagPriv evaluates privacy-oriented transformations of operational
troubleshooting evidence while making the task-relevant diagnostic relation an
explicit object of study. Three synthetic development families probe different
dependencies—cross-source equality/linkage, external-reference structure, and
temporal order/overlap—and measure resulting RCA behavior separately from
evidence support and model-visible representation exposure. The project does
not establish a universal transformation ranking or formal privacy guarantee;
its current contribution is a controlled, versioned measurement framework and
a set of directional development observations. The current repository can
reproduce software, deterministic analyses, and manuscript tables from tracked
material, but not independently inspect the exact historical provider
responses without a future archive materialization.

This summary is a project-team/assistant readability check, not an independent
collaborator interpretation.
