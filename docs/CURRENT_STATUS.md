## Transformation status

### `redaction-v1`

- Replaces only annotated sensitive fields with generic, source-qualified
  placeholders.
- Does not intentionally preserve equality or cross-source identity.
- Reports all-to-one equality as `degenerate_all_to_one`, not genuine
  preservation.
- Development provider result is complete and frozen; validation has not run.

### `hmac-v1`

- Uses domain-separated HMAC-SHA-256 over annotated sensitive scalars.
- Preserves intended shared identity for `consistent_pseudonym` annotations.
- Uses path-specific namespaces for independent/direct-identity policies.
- Keeps its 256-bit experimental key external and records only a non-secret key
  ID.
- Preserves every current Incident 001 predicate offline; literal-identity
  predicates report expected non-preservation.
- Has passed offline unit and integration tests, but has no LLM result.

## Known limitations

- Only one incident family exists, so current model scores cannot establish
  generality.
- Development and validation samples are small and generated by one family.
- No human difficulty or evidence-sufficiency study has been completed.
- HMAC privacy exposure has not yet been measured quantitatively.
- Provider determinism is not guaranteed even with fixed inputs and one call.
- Results are local/ignored; a collaboration-safe artifact distribution policy
  remains to be chosen.
- The evaluation runner currently constructs Incident Family 001 directly and
  will need a reviewed family registry before broad multi-family evaluation.
